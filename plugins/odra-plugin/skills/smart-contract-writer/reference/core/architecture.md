# Odra Architecture Overview

## What Odra Is

Odra is a smart contract framework for the Casper Network. It provides a macro-driven
developer experience where contracts are plain Rust structs, and multiple backends handle
execution: an in-memory VM for fast unit tests, a full Casper execution engine for
integration tests, and a livenet client for production deployments.

## Project layout (Odra 2.10 templates)

Single-crate templates (`full`, `blank`, `cep18`, `cep95`):

| Path | What it is |
|---|---|
| `src/` | the contracts; every module needs `pub mod x;` in `src/lib.rs` |
| `Odra.toml` | the contracts to build to wasm (`fqn = "<module>::<Struct>"`) |
| `bin/cli.rs` | the deploy script and scenarios, built as the `<project>_cli` binary |
| `bin/build_contract.rs`, `bin/build_schema.rs`, `build.rs` | generated tooling, not edited |
| `rust-toolchain.toml` | the pinned nightly |
| `.env.sample` | livenet configuration template for the CLI |
| `AGENTS.md`, `CLAUDE.md` | instructions for agents (this plugin) |
| `wasm/` | built contracts (`<Struct>.wasm`), created by `cargo odra build` |
| `resources/casper_contract_schemas/` | contract schemas, created by `cargo odra schema` |
| `resources/<chain>-contracts.toml` | addresses of contracts the CLI deployed |

The `workspace` template puts each contract crate in its own directory (`<crate>/src/`, fqn
`<crate>::<module>::<Struct>`), the CLI in `cli/cli.rs`, and the one `wasm/` directory at the
workspace root — Odra 2.10 looks for wasm files in the working directory and every directory above
it.

## Crate Map

| Crate | Role |
|---|---|
| `odra` | the framework: `odra::prelude`, the `#[odra::module]` family of macros, `odra::host` (`Deployer`, `HostRef`, `HostEnv`), `odra::casper_types` |
| `odra-test` | `odra_test::env()` (backend from `ODRA_BACKEND`), `odra_env()` (always OdraVM), `casper_env()` (always CasperVM) |
| `odra-modules` | ready-made modules: `access`, `security`, `cep18_token`, `cep95`, `erc20`, `dapp`, ... |
| `odra-cli` | `OdraCli` builder, `DeployScript`, `Scenario`, `DeployerExt::load_or_deploy`, `ContractLoaderExt`, `cspr!` |
| `odra-build` | `build.rs` support and `odra_build::contract_schema` used by `bin/build_schema.rs` |
| `odra-casper-livenet-env`, `odra-casper-rpc-client` | the livenet backend; pulled in by `odra-cli`, so a generated project needs no `livenet` feature |

## Execution Flow

```
Test/CLI call
  → HostRef method (generated by #[odra::module])
  → HostEnv::call_contract
  → HostContext::call_contract (backend implementation)
  → EntryPointsCaller (routes to the correct fn; receives the ContractEnv per call)
  → Contract function (reads/writes via ContractContext)
```

Getters (`&self` entry points) on livenet, and `#[odra(offchain)]` functions on every backend, do
not go through a transaction: the host runs the contract code locally against the chain or VM state.

## Two Context Layers

**`HostContext`** (host-side interface):
- Used by `HostEnv` for deploying and calling contracts from tests/CLI
- All methods take `&self`; implementations use `Rc<RefCell<...>>` internally
- Three backends: `OdraVmHost`, `CasperHost`, `LivenetHost`
- Since 2.10 also snapshots (`take_snapshot`/`restore_snapshot`) and the worker environments
  behind `HostEnv::concurrently`

**`ContractContext`** (on-chain execution interface):
- Used by contract code at runtime to read storage, emit events, get the caller, the call stack,
  print debug output, deploy and upgrade factory children
- Accessed via `self.env()` inside a contract impl

## Smart Pointer Conventions

The framework is single-threaded:
- `Rc<T>` for shared ownership (not `Arc<T>`)
- `RefCell<T>` for interior mutability (not `RwLock<T>`)
- `HostEnv` is not `Send`. `HostEnv::concurrently(items, |env, item| ..)` is the one way to fan
  out: each worker thread gets its own `HostEnv` (on livenet with its own node connection), and
  the closure must use that one, not yours.
